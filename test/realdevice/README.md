# 実機確認キット

Jcreate++ の動作テストは、Cluster の動きをまねたモック（`src/sim/`）の上で動いています。
ここにあるワークスペースは、**モックでは確かめられないことを Cluster の実機で確かめる**ためのものです。
期待する結果は `test/realdevice.test.ts` でモックと照合済みなので、実機で違う結果が出たら、モックか生成コードの前提が実機と違うということです。

## 準備（シナリオごとに1つ）

1. Jcreate++ で `workspace読込` → `rdN-….json` を読み込む
2. `JS保存` で JS を保存する
3. Unity で立方体などを置き、Item と Scriptable Item を付けて、保存した JS を設定する
   - 右側に出る「Unity側で必要な設定」も合わせて行う（位置を動かすシナリオは移動可能な設定が必要）
   - 詳しい手順は公開ドキュメントの「JSを保存してUnityに持っていく」
   - **Item を付けた一番上のオブジェクト**の向き（Local 表示の青い矢印）が分かるようにしておく
4. Cluster でテストする（ワールドにアップロードするか、プレビュー機能で確認）

## チェックリスト

| # | ファイル | 操作 | 期待する結果 | 違ったときに分かること |
|---|---|---|---|---|
| 1 | `rd1-position-immediate.json` | インタラクトを1回 | **1 上がる**（0.5 × 2） | 0.5 しか上がらない → 位置を設定した直後に読むと古い値が返る。「〜ずつ変える」を続けて使うブロック全般の前提が崩れる |
| 2 | `rd2-smooth-rotate.json` | インタラクト | 前に 30° 傾いた状態から、**2秒かけてなめらかに 90° 回る**。エラーが出ない | 回らない・コンソールにエラー → Quaternion の4引数の作り方か、アロー関数が使えない |
| 3 | `rd3-decimal.json` | インタラクト | **1 上がる** | 下がる → 小数の丸め（`toPrecision`）が実機で効いていない |
| 4 | `rd4-sequence-timing.json` | インタラクトしてストップウォッチ | 1 上がり、**約3秒後**に戻る | 大きくずれる → 待機の時間計算の前提が違う |
| 5 | `rd5-sequence-rerun.json` | 1秒ほど間をあけて3回インタラクト | **毎回 0.5 上がる** | 1回目しか上がらない → 一連の動作の再実行時のリセットが効いていない |
| 6 | `rd6-flag-bool.json` | インタラクトを2回 | **1回目で上がり、2回目で下がる** | 下がる→下がる → フラグと真偽値変数の統合が効いていない |
| 7 | `rd7-move-local.json` | インタラクト | 開始時に右へ 90° 向き、インタラクトで**青い矢印（向いている方）へ 1 進む** | 別の方向に進む → 「前＝+Z」の前提が実機と違う |
| 8 | `rd8-ride-forward.json` | 乗って前進キー | **青い矢印の方向へ進む**（右キーで右に曲がる） | 左や後ろに進む → 乗り物の「アイテムの前（+Z）」の計算が実機と違う |

8 は乗り物として乗れる設定（座席など）が必要です。

## 結果の記録

確認したら、日付・Cluster Creator Kit のバージョン・結果（○/×と、×なら実際の動き）を
`docs-internal/` などに残してください。×があれば、その内容を Claude Code に伝えれば原因を調べます。

## シナリオを変えるとき

`test/realdevice/scenarios.ts` を編集して `npm run realdevice:export` を実行すると JSON が更新されます。
期待する結果は `test/realdevice.test.ts` に書いてください（JSON が古いままだとテストが失敗します）。

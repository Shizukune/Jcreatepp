## いま、どんなツールになっているか

**Cluster のワールドに置く小さなギミックを、JavaScript を書かずに作るための、初学者向けのブロックエディター**です。

| 部分 | できること | 規模 |
|---|---|---|
| Web 版（ブラウザだけで使える） | ブロックを組むと Cluster Script がその場でできる。日本語のエラーと警告、動きの見本付きの説明、部品（ブロックのかたまりを自動で追加） | ブロック 74 種（パレット 9 カテゴリ）、部品 4 つ |
| 3D プレビュー | Cluster に持っていく前に、ブラウザの中で動きを確かめる（Cluster Script とほぼ同じ `$` のまね） | 物理・ネットワーク・ほかのアイテムは、ログやボタンで代わりに見せるだけ |
| 生成されるコード | 1 文ごとに日本語のコメントが付いた、読んで学べるコード。Unity 側で必要な設定（Movable Item など）も案内する | クラフトアイテムの上限（20,000 バイト）と比べて表示 |
| ガイドサイト | はじめて Unity で動かすまでの流れ、レシピ 6 つ、ブロックの説明、困ったとき | |
| 実機確認キット | Cluster で確かめるシナリオ rd1〜rd18（ブロック・生成済みスクリプト・手順書を 1 か所から作る） | **まだ結果の記録が無い** |
| Unity 拡張（試作） | `.js` をオブジェクトに付けると、必要なコンポーネントを自動で付ける。Unity の中でのプレビュー。Unity の中でブロックを組むブロックエディター（Web 版と同じ処理を Jint で動かす） | C# 約 5,300 行。Unity 6000.2 で動作、2021.3 は未確認 |

処理の流れは「ブロック → IR（中間の形） → コード」に分かれていて、Web 版・3D プレビュー・Unity 拡張が同じ処理を使っています。テストは 279 件で、生成コードのスナップショット、動きのテスト、Unity 用の処理が Web 版と 1 バイトも違わないことの確認まであります。

**向いていること**: 触ったら動く・回り続ける・ドア・スイッチと受け手・音と文字・近づくと反応する、のような 1 つ〜数個のアイテムのギミック。授業やワークショップ。

**まだ向いていないこと**: 物理を中心にしたギミック、たくさんのアイテムが連携する仕組み、プレイヤーごとの状態を持つゲーム。そして、**Cluster の実機でどこまで動くかが、まだ記録として確かめられていない**こと。

## 弱点・リスク（重い順）

### 1. 実機での結果がまだ一度も記録されていない（Claude Code）

- 場所: `test/realdevice/CHECKLIST.md` の「結果」欄が全部空
- 生成コードの正しさは、シミュレーター（`src/sim`）の上でしか確かめられていない。特に、毎フレーム `$.getPosition()` / `$.getRotation()` を読むブロック全体（回り続ける、往復、乗り物、追いかける）は、getter の遅れ方しだいで動きが変わる（rd9 で分かる）
- 次の実機テストでまず埋める（`test/MANUAL-TEST.md` の 4）

### 2. High: 保存データの読み込みに失敗すると、編集画面が止まる（Codex、確認済み）

- 場所: `src/serialization.ts:27`（起動時の `load`）、`:71`（ブロックを開く）、`src/index.ts:510`
- `Blockly.Events.disable()` のあとに読み込みが例外になると、`Events.enable()` に戻らない。そのあとは自動保存・警告・コード更新が動かない。起動時の `load(ws)` は try の外なので、壊れた保存データがあるとページ全体が動かない
- 例: 新しい版で保存した、知らない種類のブロックが入った `.json` を開く
- 直し方の案: `Events.enable()` を `finally` に入れる。別のワークスペースで読めるか確かめてから入れ替える。起動時に読めなければ空の画面で始め、そのことを知らせる

### 3. Medium: 「追いかけるギミック」が速いと行き過ぎる（Codex、確認済み）

- 場所: `src/codegen/program.ts:254`
- 止まる距離より遠ければ、残りの距離に関係なく「速さ × 経過時間」だけ進む。速い・フレームが落ちたときに相手を通り越して、行ったり来たりする
- 直し方の案: 進む量を「距離 − 止まる距離」までに抑える。大きなフレーム間隔のテストを足す
- 生成コードが変わるので、直す前に確認する

### 4. Medium: 乱数の上限・下限が小数のとき、整数モードで範囲の外が出る（Codex、確認済み）

- 場所: `src/codegen/expr.ts:48`（`randomNumberToJS`）
- 例: 1.5〜2.5 の整数 → 1 や 3 が出る。上限・下限に乱数ブロックをつなぐと、比べるときと幅を計算するときで別の値になる
- 直し方の案: 上限・下限を 1 回ずつだけ計算し、整数なら `ceil(下限)`〜`floor(上限)` にする。範囲に整数が無いときの扱いを決める

### 5. Medium: 3D プレビューが、Unity 側の設定の間違いを見せない（Codex）

- 場所: `src/sim/clusterMock.ts`（107・154・170・176 行付近）
- 登録されていない名前のアイテムや音・サブノードでも、プレビューでは成功する。初学者は「プレビューでは動いたのに Cluster では動かない」原因が分からない
- 直し方の案: プレビューに「名前が Unity 側と合っているかは確かめていません」と出す。あとで、登録したものだけを返す厳しいモードを作る

### 6. Medium: Unity 拡張の確認が、サイト公開の流れに入っていない（Codex）

- 場所: `.github/workflows/deploy.yml`、`unity/check/`、`unity/Jcreatepp/Editor/ScriptAnalysis.cs`
- GitHub Actions は `npm test` とビルドだけ。C# のコンパイルと本物の Jint での確認（`unity/check`）は手元の Windows でしか動かない
- `.js` を正規表現で読んで設定を決める処理（`ScriptAnalysis.cs`）と、ブロックから決める処理（`src/unitySetup.ts`）が 2 つある。生成コードの書き方を変えると、ずれるおそれがある
- 直し方の案: Windows のランナーで `unity/check` を動かす。2 つの処理の結果が同じことを確かめるテストを足す

### 7. Medium: Web 版の画面に自動テストが無い（Claude Code）

- 場所: `src/index.ts`・`src/index.css`（テストからは読み込まない決まり）
- カテゴリ名が読めない不具合（`3f99885` で直した）は、最初のコミットから気づかれずに残っていた
- 直し方の案: 画面の最低限の確認（カテゴリ名の文字色と背景色が違う、ボタンがある、など）を、ブラウザで開いて確かめる簡単なチェックにする

### 8. Low: ガイドに、今は無い機能の例が残っている（Codex、確認済み）

- `docs/export-to-unity.md:76`: 「マテリアルを変える → Material Set」。マテリアルを変えるブロックは今は無い
- `docs/troubleshooting.md:27`: `$.state` の名前をそろえる話。ブロックで作るときは `$.state` を直接書かないので、初学者には分かりにくい（変数ブロックの名前の話に直すのがよい）

### 9. 前から分かっていること（今回は対象外）

- Cluster の getter の遅れ方（rd9・rd17・rd18 待ち）
- Unity 2021.3 で確かめていない
- 生成コードの長いキー名（ブロック ID 入り）
- 変数の並び順が PC の言語設定で変わる（Web 版）
- 違う軸で同時に「〜秒かけて回す」と、結果がフレームの間隔で少し変わる（30〜144 fps で 2 度以内）
- Unity ブロックエディターは、ブロックのつながり方を C# で作り直している（Blockly と同じつながり方になることのテストが無い）

## はっきり良いところ

- **処理の分け方**: ブロック・IR・コード生成・シミュレーターが分かれていて、Unity 拡張でも同じ処理をそのまま使えている
- **確かめ方が何重にもある**: 生成コードのスナップショット、動きのテスト、トレースあり／なしの一致、実機確認キットと Unity 用バンドルの古さの検出、Web 版と Unity の結果の 1 バイト一致
- **初学者向けの工夫が、コードそのものに入っている**: 日本語コメント付きのコード、置き場所の警告、変数の使われ方の表示、部品、動きの見本
- **実機確認を 1 か所から作る**: シナリオからブロック・スクリプト・手順書を作るので、確かめるものを取り違えにくい
- **Unity 拡張も、作業を消さないことに気を配っている**: 時間・メモリの制限、未保存の確認、手で直した `.js` を上書きしない、知らない項目を消さずに残す
